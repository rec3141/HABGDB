HABGDB

The Harmful Algal Bloom Genomic Database: a version-controlled record of the cyanotoxin biosynthetic-gene-cluster reference panel used for shotgun-metagenomic HAB surveillance.

What this is

danaSeq's nanopore_live pipeline maps every nanopore read against a set of toxin references, one per compound: microcystin, cylindrospermopsin, saxitoxin, anatoxin-a, nodularin, guanitoxin and aetokthonotoxin. Each reference joins the biosynthetic gene cluster (BGC) sequences from several producer taxa into one multi-FASTA, so a hit counts towards that toxin whichever producer it came from. The panel was hand-built on 2026-06-11 from NCBI nuccore searches and until now lived only as unversioned files in the pipeline's mapping_refs/ directory.

HABGDB records exactly what is in that panel: every accession.version and subrange, with organism, title, length, a sequence hash and any hard-masking. It also keeps the original search queries and the inclusion and exclusion notes. build_hab_refs.py rebuilds all seven references from NCBI. The rebuild is byte-identical to the live panel, including the minimap2 indexes.

HABGDB sits alongside AISGDB (aquatic invasive species) and SARGDB (species at risk). All three use the same mapping_refs/<name>/ layout, and meta.json category decides which view a reference appears in. This repo covers the "HAB" references, which show up in the SPA's HABs view.

Rebuilding the references

The accession lists in refs/<ref>/accessions.tsv are the source of truth. .fna and .idx files are never committed.

# fetch from NCBI (retry + backoff), write .fna / contigs.json / meta.json,
# and build the minimap2 index (minimap2 -t 4 -d <ref>.idx <ref>.fna)
python3 build_hab_refs.py --outdir build

# ... and verify against the live panel (read-only)
python3 build_hab_refs.py --outdir build \
    --compare-to /data/scratch/refdbs/mapping_refs \
    --report data/reproducibility_check.tsv

# refresh the QA tables and the inventory page
python3 panel_redundancy.py --build-dir build
python3 hab_inventory.py
